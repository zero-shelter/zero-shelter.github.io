In practice

Use the terminal,
CI, or a coding agent.

Choose the workflow that fits your project. Each uses the same dependency findings.

/01

Terminal

Run a scan with Node 20 or later and supported package files, or read a saved report.

npx zero-shelter judge

/02

CI

Export SARIF and use the exit code to fail a job when new findings are reported.

npx zero-shelter judge --format sarif

/03

Coding agent

Pass findings and available commands to a coding agent, then check its changes by running judge again.

npx zero-shelter hook

First run

Run a scan.
Review the results.

Inspect the findings and available fixes. Recording a baseline is an optional risk decision, not a required installation step.

  1. 01

    Inspect

    Use supported project files or supply a saved report with --input. If no usable report is available, the command exits 2.

  2. 02

    Accept risks, if needed

    After reviewing the risks, --update-baseline records the current findings as accepted. It does not fix them. Add a reason, owner, and expiry where appropriate.

  3. 03

    Gate

    Write SARIF for GitHub Code Scanning and use the judgement result to fail on new findings.

Agent route

Work with a coding agent.

The hook adds findings to a supported editor's prompt context. It does not block or rewrite prompts, and exits quietly on errors. The agent's changes still need review and a new judge run.

The plugin provides setup, explanation, remediation, baseline, and CI skills.

Output formats

Text is for people, JSON for tools, SARIF for GitHub, and HTML for a shareable local report. Use --explain for the score and --record, then zero-shelter history, to see changes over time.
